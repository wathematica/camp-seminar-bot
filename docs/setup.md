# セットアップ

## 1. Discord Botを用意する

[Discord Developer Portal](https://discord.com/developers/applications)でアプリケーションとBotを作り、Botトークンを取得します。対象サーバーにBotを招待してください。

対象チャンネルで必要な権限：

- チャンネルを見る
- メッセージ履歴を読む
- リアクションの追加

この実装ではMessage Content Intent、Server Members Intent、管理者権限は必要ありません。カード本文は、所有者であるWebhookを通じて取得します。

## 2. 専用Webhookを用意する

通常のテキストチャンネルでWebhookを作成し、そのURLを控えます。フォーラム・スレッドは対象外です。GASとPython Botには同じWebhook URLを設定してください。

専用Webhookを使ってください。BotはそのWebhookの投票案内付きカードと旧形式カードを処理します。初回には既存の対象投稿も読み取り、リアクションと人数表示を更新します。

## 3. Googleフォームを用意する

最初の質問を「名称」にします。短文回答・必須入力にし、256文字以内にしてください。

それ以降には「形式」「概要」「使用するテキスト」「望ましい予備知識」などを自由に追加できます。回答はDiscordに公開されます。名称はカードの見出しに、それ以外は本文に表示されます。

フォーム側のApps Scriptを開き、[gas/onSubmit.gs](../gas/onSubmit.gs)を貼り付けて保存します。回答先スプレッドシート側のスクリプトではありません。

スクリプトプロパティ：

| 名前 | 値 |
|---|---|
| `DISCORD_WEBHOOK_URL` | 手順2のWebhook URL |
| `DISCORD_USE_CANARY` | 通常は `false`。既存環境のcanary方式を維持する場合は `true` |

現行GASは既存環境との互換性のため、`DISCORD_USE_CANARY` 未設定時もcanary方式になります。新規導入時は明示的に `false` を指定してください。どちらのドメインでも通信が保証されるわけではありません。

`onSubmit` のトリガーを「フォームから → フォーム送信時」に設定し、必要なアクセスを許可します。「デプロイ」は不要です。`onSubmit` をエディターから直接実行せず、実際にフォームを送信して試してください。

旧GASから移行する場合は、古い `updateCampVotes` の時間トリガーを削除します。フォーム送信の `onSubmit` トリガーは残します。GAS側のBotトークンは新構成では使いません。

## 4. 手元で試す

[README](../README.md#はじめ方)の手順で `run_local.py` を実行します。BotトークンとWebhook URLは非表示入力で、ファイルには保存しません。

成立目安人数は通常3人です。一人で色の切り替えを試す場合だけ1にします。この入力は手元の起動にのみ適用され、Docker側の設定には影響しません。

確認項目：

1. フォームを新規送信すると、名称を見出しとするカードが投稿される。
2. 1️⃣・2️⃣・3️⃣が付く。
3. 1️⃣を押すと、第一志望の人数が増える。
4. 成立目安人数に達すると緑になる。取り消すとピンクに戻る。
5. 2️⃣だけ、3️⃣だけでも対応する人数が増える。
6. 同じカードで複数の番号を押すと、最も高い志望だけが数えられる。

手元の結果は `local-test.log`、投稿記録は `local-data/` に保存され、Gitでは除外されます。同じ対象のBotを複数同時起動しないでください。

## 5. サーバーへ移す

確認できたら[Docker運用手順](operations.md)に進みます。GASは同じものを使えます。手元のBotを止めてからサーバー版を起動します。
